# OneBrain functionality, data-safety and compatibility audit

Date: 11 September 2026. Branch: `arena/01a085b4-onebrain`. Scope: repository inspection, dependency checks, local production builds, automated browser checks and fixes. **This is not an independent penetration test, physical-device certification, or a claim that all 175 requirements are finished.**

## Verdict

The audit found real defects that the previous happy-path suite did not cover. The fixes below are implemented. The existing two-screen structure is retained: **Today** and **Your space**, with contextual tools rather than additional primary screens.

“Everything works on every iPhone/Android/PC” would be an unsupported claim. The product still has unfinished software and external release gates. The full requirement ledger remains authoritative, including requirements that are not implemented.

## Implemented fixes

1. **No paid host-key fallback.** Removed host OpenAI/Gemini/ElevenLabs spending paths from Next, Workers and the legacy Express routes. In particular, configuring an OpenAI key can no longer silently enable server transcription. STT reports unavailable; TTS falls back to browser speech. Removed the unused Express OpenAI SDK. Explicit user-key requests remain subject to that user's provider plan; configure a non-billed project if free-only use is required. No hosted API is promised unlimited.
2. **Bounded requests.** Next chat/TTS validate JSON, types, lengths, history roles and content before calling providers. Requests are byte-bounded while streaming, including the platform proxy, rather than checked only after allocating the whole body. The reader has a deadline. Workers and Express chat have corresponding size/type checks. Express returns proper malformed-body/oversize errors.
3. **Provider deadlines and credential hygiene.** Gemini attempts share a 12-second deadline; community AI has a 12-second deadline and Wikipedia a shared seven-second deadline. These fit inside the browser route deadline. Keys go in headers rather than provider URLs. Removed raw Gemini error logging. Replaced the retired Gemini 1.5 fallback with 2.5 Flash-Lite; no paid provider was called to test it.
4. **One-time reminder semantics.** Same-day relative reminders retain their date and cannot turn into daily reminders. Absolute spoken reminders select the next occurrence unless recurrence is explicit. Fixed Hindi `ghante` hour handling and invalid clock values. Calendar-day arithmetic replaces adding 24 hours for tomorrow.
5. **Reminder persistence and consent.** Adding, dismissing and marking reminders await storage; save failures no longer produce success messages or clear the input. Memory-off blocks new persistent reminders. Only the explicit notification-permission button asks permission. Previously saved reminders remain until dismissed.
6. **Reminder delivery no longer waits for a nonexistent worker.** Replaced the potentially never-resolving `serviceWorker.ready` wait with registration lookup and a browser-notification fallback. Prevented overlapping watchdog ticks. These remain best-effort browser reminders, not OS alarms.
7. **Conversation boundaries.** Hydration/reload no longer combine every conversation into the current chat. Stable stored UUIDs survive hydration. New conversations reset their rolling summary and use UUID conversation IDs.
8. **Undo and deletion integrity.** Undo removes the correct saved exchange after reload and invalidates its summary. Conversation deletion is transactional; state and the delete control do not claim success when persistence fails. Message/conversation writes share one transaction.
9. **History viewer and search.** Deduplicated saved/live messages in a conversation. Search now queries all saved conversations, not just the active chat, with an explicit local scope, recent-100 result bound, accessible label and loading/error/empty states. Memory/timeline storage errors are no longer presented as empty history.
10. **Untrusted settings.** Normalize stored booleans, numbers, language, aliases and proactive preferences. A corrupted voice speed cannot crash the page. Strings do not grant consent. Failed preference reads pause new memory; failed writes clearly say changes are session-only. Avoid repeated localStorage writes on unrelated assistant state changes.
11. **Identity race.** An authentication revision prevents a delayed initial `/me` response from restoring identity after logout. Cached local profiles never restore authentication. Account/capability reads and logout have finite client deadlines.
12. **Vault concurrency.** Creation, save, restore and deletion now share a transactional compare-and-swap boundary. Stale tabs cannot overwrite or delete a newer vault. Pending mutations check the lock generation. Failed/corrupt storage ends in an explicit recoverable error rather than an endless opening indicator. Cryptography is still not independently audited.
13. **Accessibility and responsive details.** Fixed low-contrast memory labels and non-keyboard-focusable scrolling diagnostic regions found by actual loaded-panel axe scans. Increased delete-confirmation touch targets and shortened its motion; conversation action rows wrap on narrow screens. Long mixed-language content, dialogs and saved history are covered in browser tests.
14. **Real linting and dependency remediation.** Replaced the broken `next lint` command with ESLint. Fixed unsafe `finally` returns and Unicode tokenization rules uncovered by linting. Updated vulnerable test/transitive dependencies; all three packages currently report zero npm-audit findings, including development dependencies. This says nothing about undiscovered application vulnerabilities.

The initial compatibility draft could scan lazy loading placeholders too early. It was strengthened to require the actual panel controls before scanning; the resulting contrast and keyboard-scroll failures were fixed and the strengthened suite passed. An orphaned pre-upgrade local API process also caused test timeouts; it was stopped and the upgraded API restarted before the successful full local runs. Neither issue is hidden as a successful first pass.

Final desktop Today and mobile capture-review/reminder/diagnostic screenshots were captured and visually inspected; the capture pass reported no page errors. A local flow-video attempt could not run because Playwright’s FFmpeg binary was unavailable; no video or physical-device performance recording is claimed.

Browser device profiles emulate viewport/touch/user-agent settings; **Linux WebKit is not physical iOS Safari, and Chromium mobile emulation is not an Android phone**. Root-font scaling is not a complete screen-reader, OS font scaling, pinch-zoom or mobile keyboard study. Voice/background behavior is separately documented in [DEVICE-VALIDATION.md](DEVICE-VALIDATION.md).

## Still incomplete — not fixed by an audit label

The 176-row ledger (175 requirements plus the added proactive requirement) still contains **68 rows labeled Implemented within stated limits, 86 Partial, 13 Not implemented, six External verification and three scoped/documentation rows**. These are ledger labels, not a validated completion percentage. No row was silently removed to manufacture completion.

Important unfinished software includes conflict resolution/automatic memory merge, scheduled calendar-aware briefings, location reminders, full inbox triage, general cross-app plan execution, broader natural-language workflows, complete provider interoperability and enterprise retention/offboarding/entitlements. See [IMPLEMENTATION-STATUS.md](IMPLEMENTATION-STATUS.md) for the individual rows and distinctions. Some rows are intentionally constrained for safety, such as no secret dictation without verified-local speech.

Production/device gates remain:

- Real Google consent and sign-in, production callback/policy URLs, and private rotation of the previously exposed OAuth secret. Fixture sessions do not verify Google consent.
- Actual iPhone/iPad/Android hardware, supported OS versions, background/lock-screen behavior, calls, Bluetooth earbuds/disconnection, mic permission revocation, low-memory termination and real notification delivery. Your reported successful background tests remain observations, not a universal guarantee.
- Live provider authorization and read-back, source weather/FX availability, quota behavior and failure/partial-outcome handling. Tests use fixtures or intentionally blocked provider requests; no paid test, external action or deployment was performed.
- Independent security review, deployment-level abuse/rate controls, CSP/XSS review, backups/restore drills, monitoring and production operational ownership. Removing host spending does not make public endpoints abuse-proof.
- Independent PR review and repository protection. The PR remains draft; do not merge or label it production-ready based on test counts.

## Reproduce

```sh
npm --prefix frontend ci
npm --prefix workers/api ci
npm --prefix backend ci
npm --prefix frontend run lint
npm --prefix frontend test
npm --prefix workers/api test
npm --prefix backend test
npm --prefix frontend run build
# Follow PLATFORM-SETUP.md to start the local API and production Next server.
npm --prefix frontend run test:e2e
# From frontend, once Playwright engines/dependencies are installed:
npm run test:compat
```

CI installs Chromium, Firefox and WebKit, runs both browser suites, audits all dependencies, and retains failure traces/screenshots. Use the linked CI result rather than assuming that adding a browser project proves it passed.
